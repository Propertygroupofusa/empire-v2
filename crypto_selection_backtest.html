🟢 What's bullish right now: live, real-time status for every coin — not a historical replay. Reuses the exact same real checks the bot itself uses at this instant to pick a coin (25h bullish check, RSI overbought filter, BTC-relative-strength alpha) — so "Eligible now" here means a branch exiting its current coin THIS SECOND would actually be allowed to buy that coin.
What this measures: for each coin the family tree bot is eligible to trade, this pulls real historical hourly candles from Coinbase and simulates buying/selling using the exact same rules the live bot uses (target %, -2% stop, breakeven ratchet, $3.75 peak-profit giveback, real fees) — then ranks coins by what that strategy would actually have returned. This does not change what the live bot buys; it's a read-only report to inform that decision.
What would my REAL money have actually done? The table above deliberately spends a flat $150 on every coin, on purpose - it's what makes coins comparable to each other by quality alone. But your real tree doesn't have an equal $150 on every coin: it has real, uneven balances per branch. This runs the identical real replay, but simulates each coin's REAL current branch dollars instead of the flat $150 - a coin with no real branch right now still gets tested, falling back to the same $150 default so the table stays complete.
BTC-relative strength comparison: the check above only asks "is this coin up over the last ~25 hours?" - in a market where everything grinds up together, that's a weak signal. This runs the exact same real target/stop/breakeven/giveback replay TWICE per coin on the same real historical data - once as-is (baseline, identical to the table above), and once requiring the coin to be genuinely beating BTC-USD's own real return over the identical window before ever entering. Shadow mode only - this does not change what the live bot buys.
Higher-timeframe trend comparison: the Alpaca/stock side already requires a 1-hour SMA20/SMA50 uptrend before entering a long (prop_bot.py's get_higher_tf_trend) - the crypto side has never had that filter. This runs the same real target/stop/breakeven/giveback replay TWICE per coin on the same real historical hourly candles - once as-is (baseline), and once requiring the coin's own real SMA20 to be above its SMA50 before entering. Shadow mode only - this does not change what the live bot buys.
QUICK_PROFIT vs. trailing stop (historical evidence): this is the real comparison that already settled the question - QUICK_PROFIT (take any real profit the instant it clears fees) lost on every coin tested, trailing stop (hold past the real target and trail a stop behind the peak, only exiting on a genuine reversal) won on all of them. QUICK_PROFIT has since been removed as a live option entirely; this table is kept as the historical evidence for why. Shadow mode only - re-running it does not change what the live bot does.
Can we make money off the stops themselves? Right after the exit-reason breakdown showed that a real losing window's damage was mostly OLD exit types and structural forced exits rather than genuine price-based stops, the direct question came back: does price tend to recover after a real STOP HIT, and would buying back in right at the stop-exit price have actually made money? This replays that against the FULL real historical STOP HIT ledger (every coin, every real hard-stop exit ever recorded - not just one 20-trade window): the real forward price move in the hours after each stop, whether it ever recovered back to the stop's own exit price, and a simple hypothetical "buy back at the stop price, sell at a modest target or a second hard stop" trade. Shadow mode only - purely diagnostic, never wired to any real trade. No fees are modeled on the hypothetical trades and real cash availability isn't checked, so treat this as a real, honest first look, not a final answer.
What about the OTHER real losses - the forced exits? The exit-reason breakdown showed most of a real losing window's damage actually came from BRANCH BREACH / EQUITY FLOOR BREACH - a branch's own real floor/drawdown-breach safety net force-selling it, not a genuine price-based stop. Unlike the OLD exit types from before QUICK_PROFIT was removed (which can never happen again), these two are real and still live today - so the same reversal question applies: does price tend to recover after one of these forced exits, and would buying back in right at that exit price have made money? Same real methodology as the Stop-Hit test above, same honest limitations (no fees modeled, real cash availability not checked) - only the source exit type differs. Shadow mode only.
🧪 Strategy Lab (A/B/C/D) - testing a pasted outside proposal for real: a third-party writeup proposed three alternative strategies (Spot Swing Trading, an Automated Grid Bot, Hourly Momentum Trading) with no real backtest of its own - only illustrative "if this move happens, here's the math" arithmetic. This replays all three, PLUS the existing live baseline, against the identical real historical candles for every coin, so all four are directly comparable on real evidence rather than a guess.

A = Baseline (the live rules)  ·  B = Hourly Momentum (RSI > 55 + hourly uptrend, fixed 2.5% target / 1.5% stop)  ·  C = Grid Bot (buys every 1% dip, sells every 1% rise, up to 10 concurrent slices)  ·  D = Spot Swing Trading (buys a real oversold pullback near its own 5-day low, holds for a 7% target or up to 7 days)

Honest limits: none of these are wired into live trading by this backtest - Grid Bot and Swing Trading don't fit the live engine's current one-position-per-branch design at all (a grid needs several real concurrent slices; a multi-day swing hold would conflict with the ~30s per-cycle exit checks), so going live with either would need real engineering work first, not just a promote click. The Grid Bot's fee assumption also reuses this file's existing real round-trip rate rather than the lower "maker-only" rate the pasted proposal assumed - worth confirming Coinbase's actual current fee schedule before trusting that difference either way. Shadow mode only.
